Problem

Every RAG architecture blog post ends with "it depends." Teams spend weeks evaluating vector databases without a framework for why one fits their constraints. The result: wrong choices discovered in production — after ingesting 50,000 documents and signing a cloud contract that violates GDPR.

RAG Readiness pre-scores your data complexity from rules before making any LLM call, then Claude applies architecture heuristics to return one specific recommendation per component — not a comparison table. Weaviate or Pinecone. BM25 or dense. One answer, with the reasoning to defend it in a design review.

Architecture

Rules first.

Features

One answer.
Full reasoning.

Opinionated by design. Every recommendation is specific enough to act on immediately.

Opinionated Recommendations
One primary choice per component — no "it depends" hedging. If Weaviate is right for your constraints, it says Weaviate and explains exactly why. The output is a decision, not a comparison table.
Compliance-Aware
GDPR and self-hosting requirements automatically eliminate managed cloud options from consideration. Weaviate and Qdrant surface over Pinecone without the user needing to know the tradeoff existed.
Complexity Scoring
Rule-based pre-scorer calibrates recommendations to team capacity. A 50,000-document legal corpus with daily updates is scored differently from a 500-document FAQ — recommendations scale accordingly.
Interactive CLI
7-question guided mode designed for conversations — no JSON file required. Non-technical stakeholders can complete the audit without engineering support.
ASCII Pipeline Diagram
Every output includes a text-based pipeline from ingestion to generation — paste it into a Notion doc, a design doc, or a Slack message without needing a diagramming tool.
Transparent Decision Rules
The /decision-rules API endpoint exposes every heuristic the tool uses. No black box — teams can audit, override, or extend the logic for their own domain.

cd rag-readiness
cp .env.example .env   # add your ANTHROPIC_API_KEY
docker-compose up api
CLI — interactive guided audit
docker-compose run --rm -it cli audit --interactive
CLI — audit from JSON file
docker-compose run cli audit \
  --file examples/legal_contracts_use_case.json \
  --format markdown
